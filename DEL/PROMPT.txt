



完成方案（高層設計與落地步驟）
技術棧：Tkinter + ttk（多分頁 Frame）+ yt-dlp（Python API）+ FFmpeg（合併）+ logging + JSON（設定/歷史）+ threading（長任務）。
介面策略：固定 500x400（可允許拖曳放大）；首頁極簡「輸入網址 → 選擇路徑 → 下載/複製」；進階控件只在下載時顯示；右上角 A-/A+ 全域字體（預設 12）即時聯動（含彈窗）。
下載策略：優先最高畫質；失敗則保底 720p（即使無聲也完成）；自動合併音視軌（FFmpeg）；外部網站備援一鍵開啟。
狀態與回饋：訊息條（綠/紅）、狀態列、進度條+速度+ETA、日誌切換；成功清空 URL、失敗保留 URL。
持久化：視窗位置/大小、字體、下載路徑、常用前綴、解析度喜好等即改即存；歷史含檔名/解析度/大小/時間/平台/路徑與存在性即時檢查。
打包：PyInstaller 單檔；資源放 assets/，以 get_resource_path() 兼容 sys._MEIPASS；EXE 版本資訊以 version_info 統一管理。
檔案與模組規劃（避免大檔、函式短小）

5) 重複檢查與命名（相似度提示、自動 -2/-3、對話框選項）
6) 穩定性與打包（全域例外、logging、設定即時生效、PyInstaller/版本資訊）

可能難點與對策
yt-dlp 解析度行為多變：高畫質與分離流策略常變動
對策：先試 bestvideo+bestaudio；失敗自動降級 720p 模板；保留無聲保底。
FFmpeg 依賴取得：使用者環境不一定已有 FFmpeg
對策：啟動檢測，提供一鍵下載至 assets/ffmpeg/；允許手動選路徑。
UI 凍結/安全取消：長任務易卡 UI、強制終止風險高
對策：背景執行緒＋事件旗標；UI 更新透過主執行緒隊列；取消/重試走狀態機。
中文與特殊字元檔名：Windows/編碼/路徑長度問題
對策：檔名正規化與縮短策略；失敗退回臨時名；確保 UTF-8。
相似度比對與重複判斷：避免誤殺與漏判
對策：檔名正規化後用簡化相似度（如 difflib）＋歷史/現存雙檢。
PyInstaller 打包細節：資源路徑與版本資訊
對策：所有資源走 get_resource_path()；以 version-file 嵌入 EXE 詳細資料；必要時添加 hiddenimports。
字體全域聯動：含彈出視窗也要同步
對策：集中管理字體物件，建立新視窗時註冊/綁定更新事件。
建議（取捨與體驗）
MVP 簡化：先完成單任務下載＋保底 720p＋FFmpeg 偵測；歷史頁先提供最基本清單與開檔/開夾。
視窗尺寸：初始 500x400，但允許拖曳放大；內容自適應，體驗更好。
外部下載器：維持三個內建連結即可，避免使用者誤會可自訂；文字放在底部以免干擾主流程。
前綴名：首頁使用 ComboBox 快速選；完整管理放到設定分頁，避免首頁複雜。
錯誤提示：訊息條顏色強對比＋對話框摘要；失敗自動保留 URL 並建議外部工具。
更新機制：提供「檢查 yt-dlp 更新」按鈕（非強制），減少平台變動帶來的失敗率。
驗收與測試要點
YouTube / TikTok / Facebook 各測至少一支影片；成功/失敗路徑皆驗證。
無 FFmpeg → 提示並可下載；有 FFmpeg → 自動合併；下載中正確報告進度/速度/ETA。
成功清空 URL、失敗保留；歷史立即更新；存在性檢查正確；開檔/開夾能用。
字體 A-/A+ 影響全介面與彈窗；視窗位置/大小正確記憶；訊息條色彩切換正確。
打包後 EXE 可執行、資源正確、版本資訊正確。
